- Read this if the task involves the project-level "hands-off" VeruSAGE-style pilot harness under `tools/verusage_hands_off/` and `runs/verusage_hands_off/` — i.e., running an external coding agent (`opencode`) end-to-end on a stripped benchmark, capturing its transcript, and scoring the result.
- This harness is **separate from the `verusage/` package**. `verusage/` is the in-repo agent stack; this harness only borrows the benchmark tasks under `benchmarks/VeruSAGE-Bench/source-projects/` and drives a third-party CLI agent against them.
- Top-level scripts:
  - `tools/verusage_hands_off/prepare_project_pilot.py` — copies a project's `verified/` tree into a fresh workspace, swaps the target file in from `unverified/`, and (with `--strip-helper-proofs`) removes other local `proof fn` helpers so the agent only sees specs/impls + the target. Writes `verify_target.sh`, `validate_edits.sh`, `BENCHMARK_CONTEXT.md`, and a hidden `_eval/<run>/{check_solution.sh,lynette_baseline.rs,original_unverified.rs}` tree the agent must not see.
  - `tools/verusage_hands_off/run_pilot.sh` — single entry point: prepares the workspace, invokes `opencode run --format json` with the prompt + benchmark context, captures the JSONL stream, exports the full session transcript via `opencode export`, runs `verify_target.sh` + `validate_edits.sh`, computes cost, and writes a `REPORT.md`.
  - `tools/verusage_hands_off/export_session.sh` — re-export any session by ID (`opencode export <sid> > path.json`). Used to recover transcripts after the fact.
  - `tools/verusage_hands_off/compute_cost.py` — sums tokens from an export JSON or step-finish JSONL and prices using a static table (gpt-5.5 medium = `$5/$30/$0.50` per M; composer-2 / Kimi K2.5 = `$0.60/$3/$0.10`). Splits per sub-agent (Sisyphus Ultraworker, Hephaestus Deep Agent, etc.).
  - `tools/verusage_hands_off/project_prompt.md` — the prompt template applied to every run. Includes anti-cheat rules and a self-report clause; we do not run an automated cheat checker by default.
- Output layout: each run lives in `runs/verusage_hands_off/<project>__<tag>__<UTC_TIMESTAMP>/` with `codebase/` (agent-visible), `logs/{opencode_run.jsonl,opencode_run.stderr,transcript.json,cost.json,cost.txt,verify_target.out,validate_edits.out,session_id.txt,prepare.out}`, and `REPORT.md`. The hidden checker baseline lives in `runs/verusage_hands_off/_eval/<run>/`.
- Validation policy: **Verus + edit-guard only**. We rely on the agent's self-report (per `project_prompt.md`) instead of a static cheat checker. The earlier `lynette additions` mode is still available behind `LYNETTE_ADDITIONS=1` for ad-hoc use, but it over-rejects legitimate proofs (e.g., it flags any `assert(...)` added inside an executable function body even when the assert is pure ghost code).
- Two pilots have been run (gpt-5.5 medium, opencode):
  - `runs/verusage_hands_off/ironkv_singleton_seq/` — IronKV target `seq_is_unique__singleton_seq_to_set_is_singleton_set.rs` / `singleton_seq_to_set_is_singleton_set`. Verus passed, edit guard passed, ~123s, ~\$0.46.
  - `runs/verusage_hands_off/atmosphere_va_range_new/` — Atmosphere target `va_range__impl2_new.rs` / `new`. Verus passed, edit guard passed, ~690s, ~\$2.12 (Sisyphus + Hephaestus subagent).
  - Combined ≈ \$2.58. See `docs/verusage_hands_off/project_pilot.md` and per-run `logs/cost.txt` for the breakdown.
- For deeper context on VeruSAGE itself or the Verus parser/cheat tool, see [`../systems/verusage.md`](../systems/verusage.md) and [`lynette-and-vstd.md`](lynette-and-vstd.md).

warning

- Local Verus / Lynette binaries used by these runs live in `.local-tools/` (not committed; gitignored). Pinned Verus is required for IronKV; the latest Verus is required for Atmosphere because it imports `vstd::simple_pptr`.
- `runs/` is gitignored — large workspaces, transcripts, and JSONL logs stay local. Only documentation and harness code live in the repo. If you are reproducing a run on a fresh checkout, you must rebuild the local toolchain and rerun via `run_pilot.sh`.
- The copied `codebase/` directory is **not** a real cargo crate. The benchmark's `source-projects/<proj>/verified/` tree is a per-task slicing of upstream code, not a buildable workspace, so we don't ship a whole-project verifier. `verify_target.sh` is the authoritative success signal. If you need crate-wide verification, point `cargo verus verify` at the upstream `verus-lang/verified-ironkv` or `mars-research/atmosphere` repo (requires a recent Verus that ships `cargo-verus`; see `.local-tools/src/verus-latest/source/docs/CARGO-VERUS.md`).
- The agent must never read `_eval/<run>/` (it contains `original_unverified.rs`, the un-stripped reference). One earlier Atmosphere attempt was killed for doing exactly that; the harness was reorganized to keep these inputs outside the agent-visible workspace.
